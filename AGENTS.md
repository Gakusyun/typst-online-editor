# Repository Guidelines

## Project Overview

Lightweight web-based Typst editor: compiles Typst → PDF **entirely in the browser** (Typst.ts WASM compiler in a Web Worker), renders the preview with pdf.js. No backend. Fork of [Mapaor/typst-online-editor](https://github.com/Mapaor/typst-online-editor) (`README.upstream.md` is the upstream English README, kept verbatim; `README.md` — the live doc — is Simplified Chinese, keep it that way).

Licensing: repo code MIT (`LICENSE` = this fork, `LICENSE.upstream` = upstream MIT grant); bundled `@myriaddreamin/*`, `pdfjs-dist`, and `codemirror-lang-typst` are Apache-2.0; the Tinymist WASM language server is Apache-2.0 (loaded from CDN, never bundled).

Stack: Preact 11 · Vite 8 (rolldown) · TypeScript 7 (`strict`) · Tailwind v4 (`@tailwindcss/vite`) · CodeMirror 6 + `codemirror-lang-typst` · Tinymist WASM LSP (`@codemirror/lsp-client`) · pdfjs-dist 6 · `@myriaddreamin/typst.ts` 0.7.0. Package manager: **pnpm** (`pnpm-lock.yaml` is the only lockfile).

## Architecture & Data Flow

Compile pipeline — every link is load-bearing; changing one means checking the whole chain:

1. **Edit** — `CodeEditor.tsx` (CodeMirror 6: `typst_lezer()` syntax from `codemirror-lang-typst`, plus `@codemirror/lsp-client` bound to the Tinymist WASM LSP in `src/lib/lsp/`) → `TypstEditor.tsx` → `useProjectFileOperations.updateActiveFileContent` → `useProjectState.saveProject` (the `projectStorage` singleton over `src/lib/storage/safeStorage.ts`; writes are **throttled to 400 ms** and flushed on `pagehide`/`visibilitychange`/unmount, records are shape-validated before use, and a write the browser refuses surfaces as the amber banner under the header).
2. **Trigger** — `useProjectState`'s `useEffect([currentProject, onProjectChange])` notifies only when the file array's **identity** changed (the immutable rebuild makes that an O(1) "did the content change" test), reducing `Project.files` to `Record<string, string>` → `useTypstCompiler.compileDebounced` (1000 ms `debounce` from `src/lib/utils/helpers.ts`; a manual compile cancels it).
3. **Service** — `src/lib/typst/TypstCompilerService.compile()` splits text files from `data:`-URL binaries (images **and** fonts) and calls `TypstWorkerClient.compilePdf()`.
4. **Worker** — `src/lib/typst/typst.worker.ts` owns all WASM/compiler lifecycle: fetches the compiler wasm and fonts **from CDN mirrors only** (jsdmirror; nothing is self-hosted in `public/`, so compiling needs network access — the wasm bytes are memoized per worker, and typst.ts's `__wbg_init` is idempotent (`if (wasm !== undefined) return wasm`), so there is exactly **one wasm instance per worker**), installs fonts **on the live compiler** — `createTypstFontBuilder()` → `addFontData` → `TypstCompiler.setFonts` inside `build()`'s callback (which then drops the caller's resolver handle) — so a font-set change is a resolver swap plus `reset()`, never a second compiler; the lazily added emoji/CJK sets are detected from the document text (`\p{Extended_Pictographic}` / CJK ranges) and their flags are committed only after the fonts are actually in, injects user `.ttf/.otf` uploads via `mapShadow` (only paths whose version changed, and removed paths are `unmapShadow`ed), feeds every font (CDN URL or project bytes) to the builder as raw font data, resolves Typst Universe packages (`FetchPackageRegistry`), and serializes jobs through `compileQueue` — **a job a newer request superseded is answered without compiling** (`superseded: true`). The 30-minute idle timeout drops the compiler and `free()`s its wasm handle (typst.ts's `TypstCompiler` interface has no teardown; the handle it wraps does).
5. **Result** — `{type: 'compile-result', id, ok, pdf, diagnostics | error, superseded?}` (worker protocol, defined **once** in `src/lib/typst/protocol.ts` and imported by both `typstClient.ts` and `typst.worker.ts`; the client carries a failure's `diagnostics` in a `CompileError`, and `superseded` replies are silent no-ops). The worker transfers the PDF without copying it (typst.ts hands out a JS-owned buffer) and `TypstCompilerService` wraps it in a blob URL, notifies `CompileListener`s through per-listener `try/catch`; `useTypstCompiler` mirrors this into React state (`status`, `pdfUrl`, `errorMsg`, `hasCompiled`). A worker crash rejects every pending request and the next compile spawns a fresh worker.
6. **Preview** — `PDFViewer/hooks/usePdfRenderer.ts` renders the **visible page ±1** to canvas + pdf.js `TextLayer`/`AnnotationLayer` via lazy `getPdfjs()` (`src/lib/pdf/pdfjs.ts`); pages outside the window keep their layout box with their pixels released, and a superseded render pass returns instead of writing into the layers it no longer owns. The pdf.js worker is loaded from a CDN mirror but **created by this app** (`PreviewWorker`, handed to pdf.js as `GlobalWorkerOptions.workerPort`): pdf.js's own worker path memoizes a startup failure on the `PDFWorker` class and keeps `#isWorkerDisabled` set, which left the preview dead until a reload — owning the worker makes the failure observable (`Worker`'s `error` event) and a retry a fresh worker. `PdfPreview` shows it as `preview.engineFailed` and drops the empty page box.

State management: **no global store**. `TypstEditor.tsx` is the sole orchestrator; hooks live in per-component `hooks/` dirs and compose upward via props. `useProjectState` is the single source of truth for `currentProject` / `activeFilePath`; every file op immutably rebuilds `Project` and persists. Folders are virtual: created as `${path}/.gitkeep` placeholders, hidden by `buildFileTree`. The immutable rebuild is now a **contract**, not a style choice: the compile trigger compares `currentProject.files` by identity (a content change always produces a new array) and the LSP project sync keys on the path list — an in-place mutation would be silently missed by both.

## Code Conventions & Common Patterns

- **Naming** — PascalCase for component/class files (`TypstEditor.tsx`, `TypstCompilerService.ts`); camelCase for hooks (`useXxx.ts`) and plain modules (`typstClient.ts`, `helpers.ts`). `<Component>Props` interfaces colocated in the component file. Default export for components; named exports for hooks/lib. Barrels exist only at `TypstEditor/index.ts`, `PDFViewer/index.ts`, `CodeEditor/index.ts`, `FileExplorer/hooks/index.ts` — `FileExplorer/index.tsx` **is** the component, not a barrel.
- **Imports** — `@/*` → `src/*` alias for cross-module (`@/lib/...`), relative within a module (`./hooks/useX`, `../types`). `import type` for type-only imports. Preact hooks come from `preact/hooks`; Preact types (`ComponentChildren`, `TargetedDragEvent`, `TargetedMouseEvent`, `RefObject`, …) from `preact`.
- **Preact idioms** — this is an SPA: no `'use client'` directives, no server components. Preact maps `onChange` to the **native `change` event** (fires on blur), so live text inputs/textarea MUST use `onInput` and read `e.currentTarget.value`. `e.dataTransfer` is nullable in DOM typings (`e.dataTransfer?.types…`). Icons: `lucide-preact` (lucide 1.x dropped brand icons — the GitHub mark is inlined in `TypstEditorHeader.tsx`).
- **Error handling** — `try/catch` + `console.error/warn`; normalize with `error instanceof Error ? error.message : String(error)`. User-visible errors go through the `errorMsg` state (rendered in `PdfPlaceholder.tsx`), the amber storage banner in `TypstEditor.tsx`, or sparing `alert()`/`confirm()`. A compile reports through listeners (`onSuccess`/`onError`) rather than a Result type; `TypstCompilerService.compile()` resolves as `void`.
- **Async** — worker RPC correlates `crypto.randomUUID()` ids through a `#pending` Map; FIFO `compileQueue` in the worker, which answers a superseded job with `superseded: true` **without compiling it**; `compileSeq` in the service drops the rest; a worker `error`/`messageerror` rejects every pending request and the next compile builds a new worker; the debounce `.cancel()`s (cancelling does not abort an in-flight worker job).
- **State updates** — rebuild `Project` immutably; `lastModified: 0` on edits is deliberate (`ProjectStorage.save` stamps only falsy timestamps).
- **Storage** — every `localStorage` access goes through `src/lib/storage/safeStorage.ts` (`safeGet`/`safeSet`/`safeRemove`; blocked storage must not throw during render). Project writes are debounced in `useProjectState` (a 400 ms throttle + flush on `pagehide`/`visibilitychange`), and `ProjectStorage.save` never mutates its argument: it returns the stamped copy it persisted plus `persisted: false` when the browser refused the write.
- **Styling** — Tailwind v4 utilities in JSX (CSS-first config: `@import "tailwindcss"`, **no** `tailwind.config.*`; Tailwind runs through the `@tailwindcss/vite` plugin, no PostCSS config). Inline `style` only for dynamic sizing. Icons: `lucide-preact`. CodeMirror theming lives in `CodeEditor/theme.ts` (github-dark palette).
- **Typing** — `strict: true`; typed arrays as `Uint8Array<ArrayBuffer>` (TS ≥ 5.7 feature); `as unknown as` casts allowed where `pdfjs-dist`/worker typings are wrong — keep the explanatory comments. TypeScript 7 has **no JS compiler API**, which is why the lint toolchain is oxlint, not typescript-eslint.

**Recipe — add fonts:** add the CDN URL (base in `FONT_CDN_BASE`) to `CORE_FONTS` / `EMOJI_FONTS` / `CJK_FONTS` in `src/lib/typst/fonts.ts`, and the family name to `SUPPORTED_FONT_FAMILIES` (shown in the Settings dialog) — fonts are CDN-only, nothing is self-hosted in `public/`. User-uploaded fonts arrive as data URLs and are handed to the compiler as raw font bytes. These are **compiler** fonts; the interface/editor fonts of the app itself are a separate concern (see the recipe below and `src/lib/appearance/`).

**Recipe — choose app fonts:** `SettingsDialog` writes an interface font and an editor font through `useAppearance()`; `AppearanceProvider` persists them (`typst-ui-font` / `typst-editor-font`) and publishes them as `--app-ui-font` / `--app-editor-font` on `<html>`. CSS consumes the variables with the default stacks as fallback (`globals.css` sets the interface stack on `html`, defines the `font-editor` utility for editor-font surfaces outside CodeMirror, and `CodeEditor/theme.ts` sets it on the editor root). A new editor-font surface = the `font-editor` utility, not a second stack. The same `useAppearance()` carries the editor word wrap (Settings → General, `typst-editor-word-wrap`); `CodeEditor` applies it as a CodeMirror `Compartment` — it is toggled while the view lives, so it must not rebuild the view (that would drop the scroll position).

**Recipe — add a language:** add a catalog to `src/lib/i18n/messages.ts` (typed against the `en` base — a missing key fails `tsc`), then register the code in `LANGS` and its endonym in `LANG_LABELS` (`src/lib/i18n/i18n.ts`). New UI strings go in `messages.ts` only; components read them via `useI18n().t`, never as JSX literals.

## Important Files

- `index.html`, `src/main.tsx` — app entry points.
- `src/lib/typst/typst.worker.ts` — WASM + font + package resolution; heaviest file in the repo.
- `src/lib/typst/TypstCompilerService.ts` — public compile API (`addListener`, `compile`, `getCurrentPdfUrl`, `dispose`).
- `src/lib/lsp/tinymist.worker.ts` — Tinymist WASM LSP host: message bridge, diagnostics filter, package prefetch.
- `src/components/CodeEditor/CodeEditor.tsx` — CodeMirror 6 editor; owns the LSP client/workspace lifecycle. The lifecycle is keyed on `lspEpoch`: the editor header's 「重试」 bumps it to tear a failed language server down and build a fresh one, and the LSP plugin is swapped through its own `Compartment` so the view, the undo history and the scroll position survive the retry.
- `src/components/TypstEditor/TypstEditor.tsx` — wiring point for all UI ↔ compiler flows, and owner of the desktop split: the file tree (narrowest column) + editor hold the left half, the right half is one slot the preview and the AI panel take turns in (the panel takes the preview's exact width; the preview stays mounted but hidden so its page/zoom survive). Dragged widths, collapse states and the AI toggle persist through `LayoutStorage` (`typst-layout`).
- `vite.config.ts` — `@preact/preset-vite`, `@tailwindcss/vite`, `@` → `src` alias, plus `rolldownOptions.output.codeSplitting` groups (`pdfjs` / `typst` / `codemirror-core` / `codemirror-language` / `codemirror` / `vendor`). CodeMirror is split three ways on purpose: as one ~800 KB chunk every build tripped `chunkSizeWarningLimit: 500`, and the warning then told nothing — the groups keep each part under the limit so a genuine bloat still trips it. Subpath deploys use the `--base` CLI flag, not config edits.
- `tsconfig.json` — `strict`, `jsx: react-jsx` + `jsxImportSource: preact`, `types: ["vite/client", "node"]`, `@/*` alias; the compiler wasm is fetched from the CDN pin at runtime, never imported by the bundler.

## Runtime / Tooling Preferences

- **pnpm** — `pnpm-lock.yaml` is the only lockfile; no npm/yarn/bun lockfiles. Dependency changes go through commands (`pnpm add` / `pnpm remove` / `pnpm up` / `pnpm pkg set`), never hand-edited version fields; `ncu` (npm-check-updates, installed globally) + `ncu -u` for bulk bumps. `engines.node` (`>=20.19`) and `packageManager` are declared in `package.json`, and the `@myriaddreamin/*` packages are pinned **exactly** (the wasm URL in `typst.worker.ts` is hand-pinned to that version). The scripts are `dev` / `build` / `lint` / `preview` — there is no `start`.
- **Node ≥ 20.19** — declared as `engines.node` in `package.json` (Vite 8 requires it); there is no `.nvmrc`, so the `engines` field is the only pin.
- **Browser floor** — `build.target: 'baseline-widely-available'` (`vite.config.ts`) is the stated matrix. The newest runtime API the code depends on is `Promise.withResolvers` (5 call sites: `typstClient.ts`, `projectWorkspace.ts`, `projectZip.ts`), which is **Baseline widely available since 2026-09-05** (Chrome 119 / Firefox 121 / Safari 17.4). Vite only downlevels *syntax*, not APIs, so a wider floor would need those call sites replaced with a `new Promise` factory — nothing else in `src/` is newer than that.
- `node_modules/` is not checked in — run `pnpm install` before any verification.
- `@myriaddreamin/typst-ts-renderer` was removed: it had no import sites (the app only compiles to PDF in a worker, it never renders Typst to canvas).
- No test runner, no formatter (no Prettier/Biome), no CI, no git hooks. Match surrounding formatting manually.

## Testing & QA

There **are no tests, no coverage, no CI** (verified across the tree). The pre-yield QA gate is:

```bash
pnpm lint
pnpm exec tsc --noEmit
pnpm build   # runs tsc --noEmit + vite build
```

`pnpm lint` runs **oxlint** with zero config (`oxlint src`; ESLint/typescript-eslint are gone — TS 7 ships no compiler API for them to parse with). It reports **zero** warnings: the one pre-existing `no-unused-vars` warning went away with the dead `resetCompiler()` — keep it at zero.

If tests are ever added, the hard-to-test surfaces are: the worker + WASM boundary (`typstClient.ts` uses `new Worker(new URL('./typst.worker.ts', import.meta.url), {type: 'module'})`), localStorage with SSR guards (`ProjectStorage.ts`), and canvas rendering (`usePdfRenderer.ts`). Easiest pure-logic units: `src/components/FileExplorer/utils/buildFileTree.ts` + `utils/paths.ts` (`validateName`), `src/lib/lsp/documentText.ts` (`applyContentChanges` — LSP incremental semantics), `src/lib/storage/safeStorage.ts`, `src/lib/utils/helpers.ts`. Prefer a throwaway smoke script over wiring tests.

## Known Quirks

- **`TYPST_WASM_CDN_URL` in `typst.worker.ts` must match the installed `@myriaddreamin/typst.ts` version.** After upgrading `@myriaddreamin/*`, bump the pin (`typst-ts-web-compiler@0.7.0`) — and keep the `@myriaddreamin/*` dependencies pinned **exactly** in `package.json` (no caret) for the same reason; a mismatch surfaces at compile time as `wasm.__wasm_bindgen_func_elem_N is not a function`.
- All compiler assets are **CDN-only**: wasm/fonts via `cdn.jsdmirror.com` (`typst.worker.ts`), pdf.js worker via `registry.npmmirror.com` (`src/lib/pdf/pdfjs.ts` — **CDN on purpose**: CDN dependencies are preferred over bundling; the tradeoff is that the cross-origin worker module runs from a blob worker with *this page's* origin, so the mirror is trusted like a build dependency and can read what the app keeps in `localStorage`, including the AI bearer token — this is deliberately kept, self-hosting the worker would remove it), Tinymist LSP wasm via `cdn.jsdmirror.com` (`src/lib/lsp/tinymist.ts`). There is **no local fallback** — the app cannot compile offline, and CDN downloads are plain `fetch` with no timeout bound. Pinned CDN refs (`typst-ts-web-compiler@0.7.0`, `typst-assets@v0.13.1`, `typst-dev-assets@v0.13.1`, `noto-cjk@Sans2.004`, `noto-emoji@v2.047`, `shiki-tinymist@0.1.0`) must be bumped alongside upgrades. The Tinymist pin is a third-party wasm-pack build of tinymist 0.14.18 (published inside `shiki-tinymist`); its JS glue and `tinymist_bg.wasm` **must come from the same build**. A failed Tinymist fetch is terminal for that worker: the memoized promise **is** cleared (so a re-call could succeed), but `tinymistClient` terminates the worker the moment it reports `status: 'error'`, and `CodeEditor` builds its client once per mount — the editor header's 「重试」 (`lspEpoch`) tears it down and builds a fresh client + worker, which is what recovers; a reload (or the mobile/desktop breakpoint flip, which remounts the editor) does too. Every later request fails fast instead of hanging on the 60 s timeout, because the transport throws once the client is marked dead. The failure is visible as `editor.lspUnavailable` **with the failure reason and a retry button** in the editor header, plus `[tinymist] failed to start` / `[tinymist] language server unavailable` in the console; compilation is unaffected (separate worker).
- **Tinymist LSP quirks** (see `src/lib/lsp/tinymist.worker.ts`): the wasm server must not be re-entered from its `sendRequest`/`sendEvent` callbacks (defer replies/event pumping to a microtask or it panics on a wasm borrow); its analysis world cannot load fonts (the wasm build embeds text fonts but no math font), so the vacuous `no font could be found` error on math is filtered out of `publishDiagnostics`; binary project files (images/fonts) can never enter the analysis world and all project text files are pushed as memory documents (see `projectWorkspace.ts`), so `failed to load file (...)` diagnostics are dropped when the referenced path exists in the project (the candidates are recovered from the source text at the diagnostic range — every quoted literal in it — and the diagnostic is dropped only when **all** of them are project files, so a multi-literal range cannot swallow a real missing file; an empty or out-of-range slice keeps the diagnostic; the worker gets the project file list via `TinymistLspClient.setProjectFiles`); the server only publishes diagnostics for the *focused* document, so `ProjectWorkspace.openFile` reopens the attached file on every editor attach; Typst Universe packages are prefetched in `resolveFn` and published as memory documents, then recompiles are nudged once the tarball lands.
- **Tinymist document mirror (the subtle one).** `@codemirror/lsp-client` sends **ranged** `didChange` content changes once a document reaches 1024 characters and the server advertises incremental sync — and tinymist does (`TextDocumentSyncKind::INCREMENTAL`, verified at v0.14.18). The worker's `docs` map is found by mirroring those changes with `applyContentChanges` (`src/lib/lsp/documentText.ts`); storing the last change's `text` as the whole document (the old code) shreds the mirror, which the diagnostic filter and the nudge both read. The nudge (project file set changed, or a package's documents landed) re-opens each open user document with `didClose`+`didOpen` instead of sending a `didChange`: LSP wants a strictly increasing version, and the mirror deliberately stores the *client's* version (`@codemirror/lsp-client` bumps it before sending), so inventing one would put our counter above the client's. Package memory documents are evicted oldest-first at `PACKAGE_CACHE_LIMIT`, and a package that fails is retried at most `PACKAGE_FETCH_ATTEMPTS` times instead of on every analysis.
- `CodeEditor` re-sends the project file list only when the **path set** changes (a key over the paths), and again whenever `lspEpoch` builds a new client; the content side rides the editor's own change notifications plus `LSPClient.sync()`. `ProjectWorkspace` reopens documents only when a text file was really added or removed (an image, a font or a `.gitkeep` never reaches the server). The LSP plugin is attached for every text file the workspace opens, with the `languageId` derived from the extension.
- `codemirror-lang-typst`'s `typst_lezer()` bundles its own Lezer `linter()`; `@codemirror/lint`'s `setDiagnostics` is last-writer-wins, so that linter would wipe LSP diagnostics — `CodeEditor.tsx` rebuilds the `LanguageSupport` without it (`typstLanguage()`). Also: CodeMirror's own base theme pins `.cm-scroller` to `font-family: monospace`, so a custom font family in `EditorView.theme` must be set **on `.cm-scroller` as well** as the editor root — setting it on `'&'` alone leaves the text on the default stack (this is why the editor-font setting looked dead).
- `main.typ` protections are literal string checks (`path === 'main.typ'`), not `project.mainFile`.
- **typst.ts returns `diagnostics` only for *failed* compiles** (verified with both `unix` and `full` formats): a successful compile drops its warnings. The failure variant of the worker reply is therefore the only carrier — `runCompile` throws a `CompileFailure` that keeps the `string[]`, the client turns it into a `CompileError`, and `TypstCompilerService` shows those diagnostics (they beat the summary string).
- pdf.js registers a `FontFace` per embedded font while rendering a text layer (`g_d<page>_f<font>` names), and never removes them — every new PDF would add more. `usePdfRenderer` deletes those names before each render; do not widen the cleanup to arbitrary faces, it would eat the app's own registrations. The same hook owns the document lifecycle: every compile produces a new `PDFDocumentLoadingTask`, and the replaced document must be released through **that task's** `destroy()` (`PDFDocumentProxy` has no public `destroy` in the types — the tasks are paired with their documents in a `WeakMap`). Skipping it leaks the parsed document *and* its pdf.js worker per compile, which is what used to kill the tab minutes in. The same hook scales the pages to its scroll container's width, so its `ResizeObserver` re-targets by element identity: a collapsed preview unmounts the container, and the next one must not inherit the width of the one before. Two more rules ride the same hook: the render pass draws only the **visible page ±1** (`releasePage` keeps the box, drops the pixels) and the backing store is capped at **2× device pixels** — the old `Math.max(devicePixelRatio, 4)` floor made one A4 page ~32 MB of canvas and a 20-page document ~0.6 GB. Page jumps scroll **instantly** on purpose: a smooth animation reports every page in between through the same observer that drives the counter and the render window.
- **Fonts (Settings → Fonts)** are app-chrome only (a CSS-only concern: `AppearanceProvider` sets `--app-ui-font` / `--app-editor-font` on `<html>`, `globals.css` holds the fallback stacks, and compile output in `PdfPlaceholder.tsx` wears the Tailwind `font-editor` utility so the editor font covers diagnostics/errors). The pickers use the **Local Font Access API** (`window.queryLocalFonts()`), which is Chromium-only, needs a user gesture while the permission is still in `prompt`, and distinguishes a refusal by the user (`NotAllowedError`) from one by the environment (`SecurityError`) — the Settings dialog therefore enumerates from a button, falls back to a free-text family name (datalist suggestions) where unsupported, and treats a missing/denied API as silent (CSS simply falls back). `systemFontsUnavailableReason()` additionally reports *which* environment problem hides the API — insecure context, opaque origin (`file://`), a cross-origin iframe, an in-app WebView/Electron shell, iOS (WebKit), a phone/tablet, or desktop Chromium without it (old version, flag, policy, fork) — and the Settings dialog shows that instead of a generic "unsupported". TS 7's `lib.dom` has no typings for it; they live in `src/types/local-fonts.d.ts` (`queryLocalFonts` deliberately optional). A chosen family is registered as a `FontFace` (`document.fonts.add`) only when plain `font-family` cannot render it (a width probe decides — installed fonts resolve, fonts from the *user* font directory may not); registration reads the whole font file, so replaced faces are pruned (`pruneSystemFontFaces`) and a load that takes over 5 s is abandoned. A family that cannot be registered is not fatal: the reason (`SystemFontRegistrationError`) is returned and shown under the input. App-chrome choices are persisted **in the setters, not in mount effects**: writing state back on mount let a second tab with stale (empty) state clear the other tab's choice. Machine fonts feed **only** these pickers: compiles never read them (that path was tried and rolled back) — a document gets the CDN fonts plus any font files in the project.
- **Desktop layout defaults** (`TypstEditor.tsx`): the file tree starts at its minimum (200px, the narrowest column), the editor at half the window minus the file tree, and the right half belongs to the preview — the AI panel, when the user opens it, takes that same slot (identical width, the preview hidden but mounted, its page and zoom kept). The window width must be ≥ `AI_DOCK_MIN_WIDTH` (1280) for the panel to dock at all; between 768px and that, it overlays the workspace with no reserved room. The derived widths come from `viewportWidth` (a resize listener) rather than measured DOM, so the preview's width and the panel's width cannot drift apart. Both dividers are real separators: `useResizePanel` drags with **pointer capture** (`pointerup`/`pointercancel`/`blur` all end the drag, so a release outside the window cannot leave the `fixed inset-0` overlay swallowing clicks) and the same width is reachable with the keyboard (←/→ = 16px, Home/End) — a keyboard resize persists immediately, a drag persists when it ends.
- **Mobile (≤ 768px) is the inverse**: the editor alone, and the file tree, the preview and the AI panel are full pages that cover the whole screen — the app header included, so they read as pages rather than as layers on top of one. Each carries its own title bar and close button, which is what gets the user back; the header's own toggles (which open them) sit behind the open page. `AiAssistantPanel` takes `fullPage` for this, while its desktop drawer keeps `top-[var(--app-header-height,0px)]` and leaves the header reachable. One page at a time via `mobilePanel` state, deliberately *not* persisted (what `LayoutStorage` remembers is the desktop arrangement). Picking a file closes the tree so the editor comes back. `SettingsDialog` takes `isMobile` and renders as a full page there instead of a centred card. Do not wrap the mobile editor in a flex row: a flex item sizes to the code's own width and the text ends up clipped instead of scrolling inside `.cm-scroller`. The editor page is normal flow, so on a phone `100vh` stops at the safe areas and the bands above and below it are *canvas*, not app surface — that is why `html`/`body` carry `--app-bg` and `index.html` declares `color-scheme`/`theme-color`: without them those bands (and the overscroll one) render the default white next to the full-bleed `inset-0` pages.
- Folder detection is `isFolderPath(project, path)` (`FileExplorer/utils/paths.ts`): a path that has children but no file of its own. An extension-less file with nothing under it is a **file** — the old "no dot ⇒ folder" rule is gone, and `validateName` is the single gate for create/rename.
- Dead code is deliberately not kept: `resetCompiler()`, `PdfPreviewProps.fileCount/charCount`, `ProjectStorage.getStorageSize`/`isStorageNearLimit` and `ProjectStorage.delete()` were all removed. `pnpm lint` is the guardrail — it must stay warning-free.
- **AI assistant contract** (`AiAssistantPanel` + `useAiChat` + `chatCompletion.ts`): `getTarget(scope)` may return **`null`** (the active file is a binary asset) — the composer then disables Send and shows `ai.binaryFileHint` (`TypstEditor` passes `canEdit`). The endpoint must be an **absolute http(s) URL**: a scheme-less value resolves against the app's own origin, which would post the `Authorization: Bearer` header to the hosting server. Streamed deltas are buffered and flushed once per animation frame (one state write per token re-rendered the whole panel), a user stop is `stopped: true` (not an error, so the partial reply stays copyable/applicable), and an "apply" against a selection compares `content.slice(from, to)` with the snapshot the request was made from — a mismatch is refused (`ai.applyStaleSelection`) instead of being spliced into unrelated text. The stream reader is cancelled in a `finally`; the key can be forgotten from Settings → AI.
- Build noise (pre-existing): a wasm-bindgen "deprecated parameters" console warning comes from typst.ts's own `wasm-pack-shim`.
- **Deliberately not built** (weighed and turned down; revisit only if one becomes a real complaint): a project list / switch / delete menu — `ProjectStorage` keeps appending to `typst-projects-list` and only the newest project is ever opened, so old ones accumulate with no UI to remove them; smooth page-jump scrolling (the instant `scrollIntoView` is what keeps the page observer from dragging the counter and the render window back mid-jump); self-hosting the pdf.js worker (would remove the CDN mirror's `localStorage` access described above — see the CDN bullet); and encrypting or session-scoping the AI API key (it stays in `localStorage` under `typst-ai-settings`, and README documents the tradeoff).
